# 운영 옵션 확장 우선순위

## 권장 순서

| 우선순위 | 옵션 | 현재 상태 / 권장 기본값 | 이유 |
| --- | --- | --- | --- |
| 1 | 시스템에 남겨둘 최소 RAM | MinimumAvailableRam 내부 설정만 있음, 기본 1 GiB 유지 | 복구 캐시를 늘려도 다른 프로그램의 메모리 부족을 감지해 정리를 멈출 수 있다. 캐시 크기와 별도 설정이다. |
| 1 | 잠금 알림 표시 방식과 빈도 | 현재 팝업 활성, 새 잠금 알림 간 최소 5분 고정 | Popup / 로그만, 새 알림 간 최소 간격, 방해 금지 시간대를 두면 대량 잠금 발생 시 작업 방해를 줄인다. 로그는 항상 남기며 강제 종료는 계속 개별 확인한다. |
| 1 | 실행 요일과 분 단위 시간대 | 현재 시작/끝 시각을 시간 단위로만 선택, 매일/종일 기본 유지 | 야간 또는 주말에만 HDD 작업을 돌리는 운영 환경에 유용하다. 자정 경계·요일 변경·시간 변경 시 안전 중단을 검증해야 한다. |
| 2 | 이력 저장 공간 상한 | HistoryMaxBytes 내부 설정만 있음, 기본 2 GiB 유지 | 기존 90일 보관 기간과 함께 감사 DB의 디스크 사용량을 조절한다. 미해결/진행 중 기록 보존 규칙을 함께 안내한다. |
| 2 | 백그라운드 UI 시작 방식 | 현재 설치 시 운영자 자동 시작 등록, 창은 기본 tray 동작 | Windows 로그인 시 UI 자동 시작 여부와 처음부터 tray로 시작 여부를 분리하면 서비스 동작과 화면 표시를 구분해 관리할 수 있다. |
| 2 | 용량 입력 단위 | 정책은 이미 사용률/바이트 시작·종료값 지원 | GB/GiB/TB 선택은 동작 추가 없이 입력 오류를 줄인다. 표시 단위와 실제 바이트 변환을 일관되게 유지해야 한다. |

## 이미 UI에서 설정 가능한 항목

드라이브/관리 경로, 제외 경로·확장자, 보관 기간, 생성/수정 시각 기준, 시작·종료 용량, 점검·대기 간격, 실행 시간대, 작업당 최대 시간·항목·삭제 바이트, 읽기 제한, 복구 후 보호 기간, CPU/온도/I/O 경고와 이상 지속 시간, Process allowlist, 이력 보관 일수는 이미 노출되어 있다. 복구 RAM 한도는 cache-options에서 추가한다.

## 유지할 안전 규칙

파일 ID·경로 재검증, 링크/ADS 등 지원하지 않는 항목 제외, 감사 기록 실패 시 중단, 복구 캐시에 들어가지 않는 파일 건너뛰기, 등록 Root 보존, 강제 종료 승인 확인은 끌 수 있는 옵션으로 만들지 않는다. 폴더 처리와 목표 도달 후 현재 폴더 완료 규칙은 사용자가 선택한 동작을 유지한다.

이 문서는 추가 옵션에 대한 제안이며, cache-options 이외 항목은 아직 구현하지 않았다.
