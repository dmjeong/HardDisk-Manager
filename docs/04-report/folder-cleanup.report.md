# Folder cleanup report

목표 용량에 도달하면 진행 중인 폴더의 삭제 가능 항목과 비게 된 오래된 하위 폴더를 처리한 뒤 중단하도록 구현했습니다. 관리 Root 바로 아래 폴더를 단위로 묶으며, Root 바로 아래 파일은 각각 독립 단위로 처리합니다. 가장 오래된 대상이 있는 단위를 먼저 선택하고 단위 안에서도 오래된 순서를 유지합니다.

- 목표 도달을 관측하면 현재 단위가 끝날 때까지 유지합니다. 외부 쓰기로 여유 공간이 줄어도 다음 폴더를 시작하지 않습니다.
- 처음 삭제하기 전에는 RAM 복사 후에도 목표와 안전 조건을 다시 확인합니다. 삭제 후 한 번의 측정값을 이력과 중단 판단에 공통 사용합니다.
- 최근·제외·복구 보호·잠김·지원하지 않는 항목은 유지합니다. 전체 스캔, 동일 핸들 검증, 파일별 durable audit, 전역 1 GiB 복구 예산을 유지합니다.
- 취소·장치/부하 이상·정책 변경·시간대·작업 상한은 계속 적용합니다. 긴 RAM 복사 뒤에도 실행 시간 상한을 검사합니다. 단일 경로 Retry는 해당 항목만 처리합니다.
- 후보 큐에 폴더별 인덱스를 추가했습니다. 기존 감사 DB 스키마와 .NET Framework 4.8/C# 7.3, WPF MVVM 구조는 유지했습니다.

검증한 코드 커밋은 `da9f0543ad9122531030015218cfc1ae5e18569b`입니다. [Windows CI](https://github.com/dmjeong/HardDisk-Manager/actions/runs/39867537429)에서 95개 테스트를 모두 실행해 성공했습니다. 39개 추가 사례에 후보 큐 경계/대소문자, 목표 도달/동시 쓰기, 중단/상한, 재시도, 실제 NTFS 폴더 정리와 보호 대상 보존을 포함합니다. 서비스 설치·인증 IPC·제거, Visual Studio WPF 참조 평가, 실제/예시 데이터와 기본/최소 크기 화면 29장 렌더링도 성공했습니다. WPF 바인딩 오류는 없었습니다.

최신 패키지는 CI의 ExplorerManager-win-x64 artifact와 로컬 `artifacts/ExplorerManager-win-x64.zip`입니다. Policies 안내와 README/운영 매뉴얼/실제 WPF 스크린샷도 갱신했습니다.

처리는 Windows Service의 별도 백그라운드 작업에서 수행하며 여러 작업을 직렬화합니다. 기본 읽기 제한은 10 MiB/s입니다. 실제 HDD 속도·대규모 부하·장시간 운전은 운영 장비의 인수 시험 대상이며, 폴더 그룹 처리는 파일별 RAM 보관과 감사 기록을 생략하는 일괄 영구 삭제가 아닙니다. 보호되거나 건너뛴 항목이 있으면 폴더가 남을 수 있습니다.
