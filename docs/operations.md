# Explorer Manager 운영 매뉴얼

## 최초 설정

기본 설치는 전용 가상 계정의 삭제 서비스와 LocalSystem의 읽기 전용 하드웨어 센서 서비스를 등록합니다. 센서 호출이 정지하면 센서 서비스만 재시작하며 삭제 서비스의 RAM 캐시는 유지됩니다.

서비스 설치 후 관리할 폴더에 서비스 계정의 읽기·삭제·복구 권한을 부여합니다. 관리자 WPF에서 볼륨과 명시적인 하위 폴더를 선택합니다. 드라이브 루트와 Windows/프로그램/제품 데이터 경로는 등록하지 못합니다. 자동 정리를 끈 상태에서 Save policy로 저장하고 Preview 이력을 확인한 뒤 자동 삭제를 활성화합니다.

## 용량과 이력

사용률, 사용 바이트, 최소 여유 바이트는 한 정책에서 하나만 사용합니다. 시작/중단 값을 다르게 설정합니다. 이력의 논리 삭제량과 실제 여유 공간 순변화는 동시 쓰기와 삭제 지연 때문에 다를 수 있습니다. 순변화가 음수여도 실제 관측값을 보존합니다.

Dashboard에는 배치별 파일 수·폴더 수·삭제 바이트·여유 공간 순변화를 표시합니다. 폴더별 집계는 중복 없이 파일 수·폴더 수·논리 바이트·관측 여유 공간 변화를 보여 줍니다. 삭제 이력은 개별 항목의 원래 경로·상태·사유·복구 상태를 보여 줍니다. CSV 내보내기는 현재 표시한 최대 100개 항목을 대상으로 합니다.

## 폴더 단위 정리

관리 경로가 `D:\Archive`이면 `D:\Archive\BatchA`와 그 모든 하위 경로가 한 단위입니다. 단위의 가장 오래된 삭제 대상 시각으로 처리 순서를 정하고, 진행 중 단위 안에서 오래된 항목부터 정리합니다. `D:\Archive` 바로 아래 파일은 각각 독립 단위입니다.

목표 용량을 확보한 뒤에도 현재 폴더의 남은 삭제 가능 항목과 비게 된 오래된 폴더를 처리한 후 중단합니다. 처리 중 한 번 목표에 도달하면 외부 쓰기로 다시 여유 공간이 줄어도 다음 폴더를 시작하지 않습니다. 최신·제외·복구 보호·잠김·캐시 초과 파일이 남으면 폴더 전체가 사라지지는 않습니다. 등록한 관리 경로 자체는 유지합니다.

용량 목표에 대해서만 폴더 완료를 기다립니다. 작업 취소, CPU/디스크 이상, 정책 변경, 실행 시간대 종료, 시간·항목·바이트 상한은 계속 우선 적용합니다. 따라서 안전 중단이나 건너뛰기 때문에 일부 항목이 남을 수 있습니다. Retry는 선택한 잠금 항목만 재시도합니다.

기본 RAM 복사 읽기 속도는 10 MiB/s이며 Policies의 작업 상한에서 설정합니다. Windows Service 작업자가 UI와 별도로 처리하고, HDD 경합을 줄이기 위해 한 번에 한 작업만 실행합니다. 폴더 전체를 일괄 영구 삭제하는 방식이 아니라 파일 검증·RAM 보관·감사 기록 후 빈 폴더를 제거합니다.

## 복구 캐시 용량

Settings → Recovery cache의 RAM limit (MiB)에 정수로 입력하고 Save changes를 누릅니다. 기본 1024 MiB (1 GiB), 지원 범위 1~16384 MiB (16 GiB)입니다. 모든 드라이브가 공유하는 보관 예산이며 전체 프로그램의 메모리 사용량과는 다릅니다.

증가 시 기존 복구본과 캐시 세대는 유지하고 메모리는 필요할 때 할당합니다. 감소 시 오래된 복구본부터 초과분을 제거하고 빈 메모리 블록을 해제합니다. 제거된 복구본은 복구할 수 없으며 이력에 CapacityReduced 사유를 남깁니다. OS에 보이는 프로세스 메모리는 GC 상황에 따라 나중에 감소할 수 있습니다.

정리·Preview·복구가 진행 중이면 용량 변경을 거부합니다. 작업 완료 또는 취소 뒤 다시 저장합니다. 변경되지 않은 용량으로 다른 환경설정을 저장하는 것은 가능합니다. 저장 후 Dashboard/Recovery는 실제 적용 상태로 다시 조회합니다. 설정 저장에 실패하면 기존 캐시를 유지합니다. 예외적인 감사 기록 실패로 저장값과 실행 중 한도가 달라지면 정리를 중단하고 서비스 재시작을 안내합니다.

## 복구

Recovery에서 현재 캐시에 남은 항목을 선택합니다. 원래 위치 또는 별도 NTFS 폴더로 복구할 수 있습니다. 동일 이름이 있으면 새 이름을 사용합니다. 폴더 아래 남은 항목 복구는 캐시에 남아 있는 항목만 복구합니다. 자동 정리 일시정지 중에도 복구를 실행할 수 있습니다.

서비스 재시작 전에 필요한 복구를 완료하세요. 복구 캐시는 영구 백업이 아닙니다. 원래 소유자와 감사 ACL을 포함한 모든 NTFS 메타데이터를 복원하는 기능은 없습니다.

## 잠금 알람

기본 동작은 건너뛰기입니다. 다른 파일은 계속 처리합니다. 강제 종료가 필요하면 Settings의 Process allowlist에 허용할 앱 이름(예: LoggerApp.exe)을 등록합니다. 현재 운영자 소유·현재 세션의 앱만 종료할 수 있습니다. 권한 부족, 서비스, 보호 프로세스, 디렉터리 잠금에서 프로세스를 확인할 수 없는 경우에는 종료하지 않습니다.

## 장애 대응

- 서비스 연결 실패: Windows 서비스 상태와 관리자 실행 여부를 확인합니다.
- IdentityMismatch/볼륨 없음: 미디어 교체 여부를 확인하고 정책을 새 볼륨에 다시 등록합니다.
- ScanIncomplete/ScanError: 접근 권한, 예외 경로, 스캔 제한 시간을 확인합니다.
- AuditUnavailable: 제품 데이터 볼륨의 공간·ACL·DB 상태를 점검합니다. 신규 삭제가 중단됩니다.
- PausedByLoad: CPU/온도/RAM과 디스크 부하를 확인합니다.
- PausedByHealth: 미확인 Critical 저장장치 알람을 점검한 뒤 확인 처리합니다.
- 센서 Unsupported/PermissionDenied/Stale: 대상 장비·드라이버·서비스 권한을 확인합니다.
- 캐시 때문에 용량 미달: 미리보기에서 큰 파일 분포를 확인합니다. 임의 영구 삭제로 전환하지 않습니다.

설정과 감사 DB는 `%ProgramData%\ExplorerManager\Data\manager.db`, 진단 로그는 같은 폴더의 `service.log`입니다. 서비스가 중지된 상태에서 메타데이터를 백업할 수 있습니다. 파일 본문은 이 DB에 포함되지 않습니다.

## 업데이트와 제거

새 패키지의 Install.ps1을 관리자 권한으로 실행합니다. 서비스 중지 시 RAM 캐시가 사라집니다. 제거는 Uninstall.ps1을 사용합니다. 정책과 이력은 ProgramData에 남습니다. 자동 시작은 설치한 운영자 계정의 ExplorerManager.Desktop 예약 작업으로 관리합니다.

72시간 연속 운전, 100만 파일·16볼륨의 대규모 부하, 실제 모델별 센서 정확도는 설치 장비에서 현장 인수 시험으로 확인합니다.

## Interlocks 운영

Dashboard의 Interlocks는 각 조건의 Clear/Pending/Tripped/Recovering/AwaitingReset/Unknown 상태와 차단 여부를 구분합니다. Settings의 RAM reserve는 캐시 예산과 별개인 시스템 가용 RAM 하한(기본1024 MiB)입니다. RAM 부족·지정 앱 실행·측정 오래됨은 즉시 차단하며 CPU·온도·활성 디스크 지연은 Trip delay(기본60초)를 적용합니다. 모니터링은 2초 주기로 측정하며 watchdog은 1초 주기로 진행 중 정리의 취소를 확인합니다.

Recovery delay(기본60초)는 안전한 측정이 연속으로 유지되어야 하는 시간입니다. 수동 Reset 옵션이 켜져 있으면 AwaitingReset에서 운영자가 Reset interlocks를 실행합니다. Pending 위험, 아직 진행 중인 위험, 회복 대기, 트립 후 미지원/누락 측정은 Reset할 수 없습니다. 래치는 서비스 재시작에도 유지됩니다. Pause는 별개이며 Reset은 Pause를 해제하지 않고 Resume는 리소스/프로세스/디스크 차단을 해제하지 않습니다.

감사 오류는 원인을 해결하고 Reset할 때 실제 감사 기록 쓰기를 검증합니다. 저장된 캐시 크기와 실행 크기가 다르면 Reset도 거부하고 서비스 재시작을 요구합니다. Critical 디스크 알림은 별도로 원인을 확인한 뒤 Acknowledge하며 실제 위험 측정이 남으면 계속 차단됩니다. InterlockTripped/InterlockCleared/InterlocksReset 전이는 감사 DB에 기록합니다. 현재 폴더 완료 규칙보다 Interlock이 우선하며 진행 중인 RAM 복사는 취소하고 원본을 보존합니다. 차단으로 끝난 작업은 그 자리에서 자동 재개하지 않으며, 조건 해소 후 정책 점검 주기·쿨다운에 따라 새 작업으로 스캔합니다.

앱 차단 목록은 실행 파일 이름(.exe)으로 입력합니다. 해당 이름의 프로세스가 하나라도 실행 중이면 차단하고 상태 조회 실패도 차단합니다. 프로세스를 종료하지는 않습니다. 외부 PLC/설비 프로토콜은 연결 사양을 정의하지 않았으며 현재 기능은 서비스 내부 리소스·앱 조건입니다.

## 알림, 요일, 이력 옵션

Notifications에서 잠금 알림의 Popup / Tray notification / Log only와 최소 간격(0~86400초, 기본300초)을 선택합니다. 같은 조회에서 여러 알림이 발생하면 한 건으로 묶어 알립니다. 간격 중 억제한 항목은 Alerts에 남고 나중에 팝업이 연속 누적되지 않습니다. 설정을 저장하기 전의 초안은 알림 동작에 영향을 주지 않습니다. 자동 강제 종료는 추가하지 않았습니다.

Schedule의 요일은 자정 이후에도 시작 요일을 따릅니다. 시작 포함/종료 제외이며 종료24:00을 지원합니다. 예: Friday 22:30–06:15는 Saturday 06:14까지 포함합니다. 선택 요일이 없거나 HH:mm이 잘못되면 저장을 거부합니다. 설정 변경은 진행 중인 해당 정책을 중단합니다.

History limit은10~102400 MiB, 기본2048 MiB입니다. 더 낮은 보관 기간/용량을 저장하면 정리를 실행하고 이후 주기적으로 유지합니다. 안전하게 제거할 수 있는 오래된 항목·성능 표본·확인된 알림부터 정리하고 복구·미완료·미해결 기록과 요청 재시도 영수증은 보호합니다. 이 보호 데이터 때문에 상한을 지킬 수 없으면 HistoryLimitProtected 이벤트를 기록합니다. 상한은 SQLite의 사용 중인 페이지 기준이며 파일의 물리 크기와 같지 않을 수 있습니다.
