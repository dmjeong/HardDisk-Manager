# UI 개편 검토

## 설계 대응

- 좌측 탐색/페이지 헤더/서비스 상태/작업 푸터: 공용 TabControl 템플릿으로 구현.
- 개요: 드라이브 수·여유 공간·활성 정책·미확인 알림, N개 용량 카드, CPU 추이, 복구 캐시, 최근 정리 작업.
- 정책: 기본/정리 기준/제외/고급의 구역별 편집, 저장·미리보기·수동 정리·삭제 구분, 선택 없음 안내.
- 삭제 기록: 로컬 시각, 사람이 읽을 수 있는 용량, 경로 말줄임/툴팁, 폴더 집계, 검색/CSV/페이지 이동 유지.
- 복구: RAM 한도/퇴출/재시작 설명, 캐시 사용률과 복구 작업.
- 리소스: 실제 센서 단위를 유지하는 수치, 눈금/단위/표본 축/측정 대기를 표시하는 3개 I/O 차트.
- 알림: 목록과 선택 항목 상세, 파일 잠금 전용 대화상자, 기존 재시도·종료 확인 동작 유지.
- 설정: 백그라운드 제어, 기록 보관, 리소스 임계값과 앱 허용 목록.
- 접근성: 키보드 탐색/포커스/비활성/오류 테두리, 입력란의 접근성 이름, 네이티브 창 프레임 유지.

## 검토에서 보완한 사항

1. 읽기 전용 용량 값은 ProgressBar에 명시적으로 단방향 바인딩.
2. 선택 메뉴의 글자색/굵기가 본문으로 상속되지 않도록 메뉴 헤더 안에 제한.
3. 누락/무효/연결 실패 표본은 선으로 이어지지 않게 NaN 간격으로 기록. 연결 실패 시 센서 표를 비움.
4. 오프라인 등록 볼륨도 유지하므로 요약은 '관리 드라이브'로 표기. 여유 공간 합산은 유효한 온라인 용량만 사용.
5. 예시 화면의 데이터는 별도 클라이언트가 제공하고 실제 삭제·복구·저장·파일 선택·승격을 실행하지 않음.
6. CI 데스크톱이 작아도 실제 WPF 컨트롤을 요청한 클라이언트 레이아웃 크기로 렌더하고 크기를 검증.

## 검증

[Windows CI](https://github.com/dmjeong/HardDisk-Manager/actions/runs/39864809979)에서 전체 빌드, 56개 시험, 디자인 타임 참조 평가, 서비스 설치/IPC/제거를 검증했다. 실제 서비스 화면 및 예시 데이터 화면을 1440×920과 1120×720으로 28장, 파일 잠금 대화상자를 1장 캡처하고 바인딩 오류를 검사했으며 오류는 0건이었다.

센서 값의 정확도와 지원 여부는 운영 장비에서 확인해야 한다. 이번 UI 변경은 하드웨어 센서 수집 방식과 삭제 엔진을 변경하지 않는다.
